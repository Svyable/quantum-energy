# Correction — v3.9 dynamic-import test harness

## Error

The first execution of the new v3.9 publication CI gate failed in all six matrix jobs before any scientific calculation ran. The helper in `tests/reproducibility_gate.py` created a module with `importlib.util.module_from_spec()` and executed it without first registering the module in `sys.modules`.

The imported v3.8 benchmark defines a `@dataclass`. Python's dataclass runtime introspection expects the executing module to be present in `sys.modules`, as it is during a normal import. The custom loader violated that expectation and raised:

`AttributeError: 'NoneType' object has no attribute '__dict__'`

## Impact

- No v3.7 or v3.8 numerical result failed.
- The failure occurred in the newly introduced CI-loader infrastructure before the benchmark calculation or raw-spectrum self-tests executed.
- No physical claim or published calculation is superseded by this error.

## Correction

`load_module()` now inserts the module into `sys.modules` before `exec_module()`, and removes it again if execution raises.

This mirrors normal Python import semantics and allows dataclass/runtime introspection to resolve the module namespace correctly.

## Verification required

The corrected commit is not considered successful until the full six-job GitHub Actions matrix completes and the publication gate, independent SI check, frozen-CSV comparison, and raw-spectrum smoke test all pass.

## Provenance

- Failing workflow run: GitHub Actions `scientific-reproducibility`, run `33003278831`.
- Observed on Python 3.12/3.13/3.14 and both pinned scientific stacks because the defect was in the common custom loader.
