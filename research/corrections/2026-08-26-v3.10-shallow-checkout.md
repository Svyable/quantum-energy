# Correction — v3.10 provenance ancestry check and shallow checkout

## What failed

The first v3.10 CI run (`33008578861`) failed in all six Python/scientific-stack jobs at the new **Verify scientific provenance and record runtime fingerprint** step, before any scientific numerical test ran.

## Cause

`actions/checkout` uses a shallow checkout by default. The v3.10 verifier intentionally requires its frozen v3.9 anchor commit to be an ancestor of the tested `HEAD`:

`git merge-base --is-ancestor <anchor> HEAD`.

With only shallow history, Git cannot establish that ancestry relation even when it is true in the canonical repository. The failure was therefore a CI-history availability defect, not a scientific-fixture mismatch.

## Correction

The checkout step now explicitly sets:

`fetch-depth: 0`

so the ancestry proof has the required commit history.

## Scientific impact

None. No v3.7/v3.8 fixture, physical calculation, expected result, material claim, or uncertainty estimate was changed. The failure occurred before the publication numerical gates executed.

## Why the ancestry check remains

Removing the anchor check would make the provenance gate weaker. The correct fix is to provide the history required by the declared invariant, not to delete the invariant when it first fails.

## Publication status

v3.10 remains **not reproduced** until a fresh PR run passes both the corrected provenance gate and all existing v3.9 numerical gates across the complete CI matrix.
