# v3.41 deployment decision — make discovery measurable

## Decision

Treat agent/search discoverability as a **measured collaboration interface**, not as a vanity metric.

Before spending effort on broad promotion, the project should first demonstrate that an unfamiliar agent starting from the public project URL can:

1. find the canonical current specification and evidence map;
2. distinguish `main` from unmerged review work;
3. find reproduction/correction/contribution paths;
4. correctly report the project's explicit non-claims;
5. avoid converting synthetic/model work into physical evidence.

## Why this is strategically useful

A technically serious open project can still fail to attract collaborators if the entry surface is ambiguous or search/agent systems retrieve an inflated summary. A measured discovery benchmark lets us improve navigation without weakening scientific language.

The v3.41 score is therefore a **documentation/agent-interface KPI only**. It is not a science, product, market, or investor-performance KPI.

## Gate

Do not claim the project is “agent discoverable” from the software fixtures alone.

After Pages is enabled, run the unchanged benchmark prospectively on at least three independently configured public agents. Record model/version, tool/browser configuration, date, inspected URLs, raw response JSON, and score.

Suggested first deployment gate:

- no critical misstatement in any qualifying run;
- median score >=85;
- every run locates `technical/current-specification.md` and `research/evidence-map.md`.

These are provisional engineering gates and must be labeled as such.

## Failure handling

A failure is useful. Diagnose whether the cause is:

- missing/stale metadata;
- search indexing;
- ambiguous landing-page wording;
- canonical-vs-PR confusion;
- inaccessible file paths;
- benchmark contamination;
- agent reasoning/reading failure.

Fix the smallest interface problem, version the change, and rerun prospectively. Do not respond to a failed discovery benchmark by making stronger scientific claims or adding misleading keywords.

## Cost/capital implication

This increment does not justify paid advertising, SEO vendors, or new scientific equipment. The highest-value near-term action is low-cost metadata/site deployment plus external-agent testing.

## Open-source boundary

Public discoverability should make correction and reproduction easier. It does not resolve the repository's still-open software/data/hardware licensing decision.
