# v3.43 venture decision — formal open licensing remains blocked

## Decision

Do **not** describe the repository, diligence room, or future release as formally open-source/open-hardware merely because the repository is public. Treat v3.43 as a review proposal for an explicit artifact-class license split.

## Proposed split

- software → `Apache-2.0`
- documentation/research text → `CC-BY-4.0`
- structured project-owned data → `CC-BY-4.0`
- hardware/CAD source → `CERN-OHL-W-2.0`

These are engineering/governance recommendations pending human and appropriate legal review. They are not currently effective grants.

## Commercial / deployment value

Clear reusable terms reduce diligence ambiguity for collaborators, facilities, researchers, manufacturers, and future licensees. The value is not exclusivity; it is reducing uncertainty around what may be reproduced, modified, redistributed, and integrated while keeping attribution/provenance visible.

## Spend / release gate

A formal tagged release remains blocked until all v3.43 machine prerequisites are explicitly satisfied. No partner or investor material should imply that missing licensing has already been resolved.

## Null / downside case

A poorly scoped blanket license could accidentally imply rights the project does not own, create inconsistent terms across software/data/hardware, or make later contributor provenance harder to untangle. Therefore the conservative default is `BLOCKED`, not silent permission.

## Best next increment

Build the path-level rights/provenance inventory and resolve exceptions before committing effective license texts/notices.
