Use the merged PR #6 implementation as the sole canonical v3.19 R2 calibration-covariance path for partner handoff, data-room references, future facility execution, and investor-facing reproducibility claims.

## Why this matters commercially

A diligence partner or facility must be able to identify one authoritative calculation path from raw data to uncertainty outputs. Parallel overlapping estimators without an authority rule create avoidable model-risk, audit friction, and the possibility of cherry-picking whichever implementation produces the preferred result.

## Gate

Before any R2 calibration result is described outside the repository as reproduced or experimentally supported:

1. use the canonical implementation listed in `machine/analysis-registry.json`;
2. bind the exact commit/configuration in the facility packet;
3. retain all QC/excluded rows under frozen rules;
4. run the prospective holdout without estimator tuning;
5. if the holdout fails, narrow/revise the model rather than switching silently to a different historical branch.

## Claim boundary

This is a reproducibility/governance improvement, not a performance milestone. It adds no device result, commercial efficiency claim, facility capability claim, or quantum-mechanism evidence.
