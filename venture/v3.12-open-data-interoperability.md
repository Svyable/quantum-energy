# v3.12 — open data interoperability as deployment infrastructure

## Change

The program now has a facility-neutral weak-EL data contract rather than relying on screenshots, processed summaries, or one laboratory's proprietary export format.

## Public-benefit value

A small open package lowers the cost for independent laboratories to submit calibration/reference measurements, rerun the same electrons-in -> photons-out analysis, compare instruments without sharing proprietary control software, and expose disagreements in background, linearity, wavelength, and radiometric conventions.

This is infrastructure for distributed replication, not a proprietary moat.

## Capital effect

Before buying a dedicated weak-EL station, the project can ask multiple facilities to export the same reference experiment in the same schema. The most useful comparison becomes empirical: which facility can represent its calibration and uncertainty transparently, which passes the unchanged validator, and which achieves the required repeatability and signal range.

This reduces equipment-lock-in risk and makes external-core spending more comparable.

## Scale-up implication

The schema separates raw counts, calibration, acquisition metadata, and derived physics. That separation is transferable to later automated/in-line process metrology. Future production systems may use different sensors, but preserving raw signal + calibration + process metadata keeps the control layer auditable.

## Risk / limitation

v1.0 assumes one stationary wavelength/radiometric calibration per package. A facility with time-dependent calibration, detector stitching, multiple gain states, or channel-dependent integration may require schema v1.1+. Such cases should extend the open format rather than be hidden in facility-specific preprocessing.

## Release gate

Do not treat a partner facility as AT-04-qualified merely because its files validate structurally. Qualification still requires empirical accuracy, repeatability, uncertainty, injection controls, reciprocity cross-checks, and reference-device stability.
